## Publishing approval checklist

Before publishing:
- Verify every factual statement against a reliable source or firsthand evidence.
- Confirm project status and all metrics.
- Label hypotheses and vendor claims.
- Remove private customer data, lead lists, credentials and confidential documents.
- Obtain permission for customer names, logos, testimonials and identifiable work.
- Confirm asset rights, links, tags, spelling, accessibility and mobile rendering.
- Review the exact copy, media, destination and publication time.
- Keep approval enabled and record the live URL after publication.

Require separate explicit approval for DMs, emails, prospect outreach, pricing or contractual replies, customer announcements, payments, purchases, ads, domain changes and autonomous operation.

## GitHub separation

If Foundable GitHub sync is used, place website code in a separate portfolio repository. Do not sync a generated website codebase into CR. This repository remains the operations system for research, decisions, product, sales, operations and finance.

## Corrections

If inaccurate content goes live, stop scheduled copies, correct or remove it, record the error and correction date, update the source document and notify affected people when materially misleading.
