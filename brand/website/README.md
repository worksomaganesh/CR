## Project showcase standard

Every project card should include:
- Exact name and one-sentence purpose.
- Status: concept / research / prototype / tested / deployed / maintained / archived.
- Problem or question being explored.
- What the founder personally researched, designed, implemented or reviewed.
- Technologies actually used.
- Features that exist in the current version.
- Verification: tests, manual checks, demo steps and limitations.
- Public repository/demo/write-up where safe.
- Next step.

Evidence levels:
- Concept: idea documented; no implementation implied.
- Research: desk research only; no customer validation implied.
- Prototype: initial implementation; production readiness not implied.
- Tested: named checks have passed within a stated scope.
- Deployed: live in a named environment with a verifiable link.
- Customer-validated: direct user evidence exists; describe sample and limits.
- Paid: payment cleared; share commercial details only with permission.
- Maintained: ongoing support is actually being provided.

Never invent performance metrics, customers, savings or adoption. Do not claim sole authorship of generated or collaborative work; describe the founder's actual contribution.

## Contact and publication gate

Use only a contact method the founder is comfortable publishing. Review all copy, links, claims, images, contact details, privacy implications, mobile layout, accessibility and broken links before publication. A preview is not a substitute for checking the live site.
